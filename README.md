# 工厂劳保鞋尺码发放与到期换领系统

零依赖（仅 Python 3.10+ 标准库）实现：SQLite 保存完整发放链路，本地目录存放磨损照片，
进程内后台任务生成到期与缺码候补提醒，模拟适配器提供门禁工号校验与旧鞋处置回执。

## 一条命令启动

```bash
./run.sh                 # 重置演示数据并启动 http://127.0.0.1:8000
PORT=8200 ./run.sh       # 换端口
```

启动后在登录页选择身份：

| 身份 | 账号 | 权限 |
|---|---|---|
| 主管 | M01 周主管 | 调整岗位/防护等级、审批提前换领、审批旧鞋遗失豁免 |
| 仓管 | K01 钱仓管 | 尺码档案、试穿发放、库存出入、旧鞋回收（**不能修改岗位等级**） |

其他命令：

```bash
python3 -m safety_shoes.seed            # 只准备演示数据
python3 -m safety_shoes --no-reseed     # 保留数据启动
python3 -m unittest discover -s safety_shoes/tests    # 47 个测试
```

## 业务规则

- **岗位授权 → 可领规格**：S1 基础防砸 / S2 防水 / S3 防穿刺 / S4 电绝缘 / S5 耐高温；
  鞋款声明其覆盖的防护等级（如 HX-300 防穿刺靴可发 S2、S3），岗位等级不匹配不能试穿。
- **试穿确认锁定**：试穿可多次调码并留痕；点“确认”后锁定左右脚尺码、扣减库存、生成发放单。
  库存不足整体回滚，试穿单仍可重试。
- **有效鞋唯一**：同一员工同一防护等级只能有一双 `active` 鞋（数据库部分唯一索引 + 服务层复查双保险），
  重复领用在发起试穿时即被拦截。
- **两处仓库并发**：所有写操作在 `BEGIN IMMEDIATE` 事务内复查；两仓库同时给同一员工发鞋，
  唯一一双库存被两人抢时，都只有一方成功。
- **换领前置条件**：只有①正常到期（到期日前 30 天窗口内，登记即批准）或
  ②主管批准的损坏/提前磨损申请，才能创建换领单。
- **先旧后新**：领新鞋必须先交回旧鞋（可用→清洁复检；报废→待处置批次），
  或登记旧鞋遗失并由主管批准豁免；否则发不出新鞋。
- **左右脚异码**：从两个尺码各扣一只，余下两只汇入 `MIX-POOL` 异码库位。
- **缺码候补**：缺码时登记候补；任意仓库入库补齐后，后台提醒任务自动通知。
- **跨岗位调动**：主管改等级生成调动记录，原岗位鞋交回/豁免结算后才能领新等级鞋。
- **使用期限**：发放日 + 鞋款寿命月数（默认 12 个月），月末截断（1/31 + 1 月 → 2/28）。

## 演示样例（种子预置）

| 工号 | 场景 |
|---|---|
| E1001 | 15 天后到期，可在“到期队列”登记到期换领 |
| E1003 | 铸造工提前磨损，三张磨损照片齐全，**待主管审批** |
| E1004 | HX-200/42 两仓缺码，**缺码候补**中（给该规格入库即触发提醒） |
| E1005 | 冲压 S3 → 仓库理货 S1，**调岗旧鞋待结算**（刷门禁有警告） |
| E1006 | 旧鞋遗失：换领已批准、**豁免待主管审批**，新鞋暂发不出 |
| E1008 | 左右脚差一码（42/43） |
| E1009 | 旧鞋交回，**清洁复检中**（通过则回库） |
| E1010 | 旧鞋报废，**待处置批次**（调出产生模拟回执） |

## 页面

- **总览**：8 项指标 + 进程内提醒（到期/候补）
- **员工资格**：突出岗位等级徽章与当前有效鞋款；员工详情含尺码档案、调岗、损坏申请三照片位
- **库存矩阵**：行=鞋款、列=尺码（35–46），格内直接显示剩余数量；A库/B库 两个仓
- **试穿发放**：按岗位授权规格选鞋、左右脚独立选码、调码、选仓库确认
- **到期队列 / 损坏审批 / 旧鞋处置 / 缺码候补 / 门禁模拟**
- 界面：工业白 `#F4F6F8`、钢蓝 `#2F5D7C`、荧光黄 `#F5D00F`；
  移动端矩阵改为换行卡片、数据表改为堆叠卡片，**不出现横向滚动**

## 磨损照片

提交损坏申请时固定三个照片位：**① 鞋底 sole ② 鞋头 toe ③ 鞋帮 upper**，缺一不可；
支持手机直接拍照上传（留空自动生成占位图）。文件保存在 `safety_shoes/data/photos/`。

## 结构

```
safety_shoes/
├── config.py            # 配色、防护等级、鞋款覆盖、期限窗口
├── db.py                # SQLite schema（含 active 鞋部分唯一索引）
├── services.py          # 全部业务规则（事务、并发、权限）
├── reminders.py         # 进程内提醒线程（到期 + 候补到货）
├── seed.py              # 演示数据
├── adapters/
│   ├── door.py          # 模拟门禁工号
│   └── disposal.py      # 模拟处置回执
├── web/                 # http.server 路由 + 函数式模板 + 样式
└── tests/               # 47 个测试（unittest，无第三方依赖）
```

## 测试覆盖

- 有效鞋唯一（服务层 + 数据库约束双重验证）
- 两仓库并发发放（多线程 Barrier 同时确认，仅一方成功）
- 使用期限计算（月末截断、到期窗口、逾期）
- 豁免审批（遗失待批阻断、批准放行、驳回须交回、仓管无权）
- 岗位权限（仓管不能改等级/审批、主管可调岗与审批）
- 试穿调码、左右脚异码、缺码候补到货提醒、清洁复检回库、报废处置回执
- HTTP 端到端：登录、全部页面渲染、表单走完整换领链路
